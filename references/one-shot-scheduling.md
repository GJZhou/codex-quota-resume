# 一次性调度参考

## 调度契约

本技能创建的是绑定当前聊天的一次性 heartbeat，而不是长期 cron 任务或持续轮询器：

- 从创建时刻起延迟 5 小时；
- 到时运行一次检查；
- 检查完成后结束；
- 不满足条件不发送消息，也不安排下一轮；
- 调度创建失败时报告失败，不伪造计划执行时间。

通过 `mcp__codex_app__automation_update` 创建或更新自动化。使用工具支持的一次性/相对延迟表示，不在用户可见内容中展示原始 RRULE。自动化名称应包含 `Codex quota resume` 和短目标标识，但不要包含敏感信息。

## 自动化提示内容

自动化提示必须是可直接执行的业务语言，至少包含：

1. 这是一次性额度恢复检查；
2. 只处理创建时确认的线程 ID 和 host ID；
3. 必须检查线程非运行、明确额度耗尽中断、当前额度恢复；
4. 条件不满足就跳过该线程；
5. 通过 `send_message_to_thread` 只发送默认续接消息或已登记的补充消息；
6. 每个线程只发送一次，完成后不再轮询；
7. 不输出凭据，不扩大目标范围。

## 已有任务处理

创建前查看当前自动化配置，按名称、目标线程和未完成状态查找相同任务：

- 找到完全相同的待执行任务时，向用户报告已有任务，避免重复创建；
- 找到目标相同但时间不同的任务时，说明差异并让用户决定是否更新；
- 找不到匹配任务时创建新任务；
- 更新时保留未要求改变的通知和执行字段。

## 最终报告

创建成功只报告：任务名称、执行时间、目标数量、检查规则和“尚未发送续接消息”。

执行结束报告每个目标的结果和证据边界；不要泄露原始聊天内容、认证信息或自动化内部令牌。
